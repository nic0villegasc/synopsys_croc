# "Hey Croc" keyword spotting on Croc (single-core Ibex)

A wake-word / keyword-spotting example for Croc, built to the **same recipe as the
MNIST MLP**. A quantized DNN (**250 → 32 → 32 → 12**) classifies a 1 s clip from
its MFCC features, running bare-metal on a single Ibex core in 16 KB of SRAM.

It deliberately **reuses the MNIST kernel unchanged** (`nn_linear.c`): a DNN
keyword spotter is just stacked FC + ReLU layers, so there is no new compute
code — only a new model, a new `main`, and a new exporter.

- **Model basis:** the DNN from *Hello Edge* (Zhang et al., arXiv:1711.07128).
- **Data basis:** Google Speech Commands (Warden, arXiv:1804.03209).

---

## Scope: what runs on-chip

The chip classifies from **precomputed MFCC features** (embedded as the test
vector, exactly as the MNIST example embeds a test image). The MFCC front end
(framing, FFT, mel filterbank, log, DCT) is a **separate DSP block** — budget it
at roughly **3–5 KB of code plus ~1–2 KB of FFT twiddle tables** when you add it,
and characterize it as its own line in the memory table. Keeping it separate
means the numbers below are the *model* footprint, which is the comparable figure.

Retargeting to a true binary "Hey Croc" wake word is a one-line change
(`LABELS = ["background", "hey_croc"]`); the architecture and footprint are
essentially unchanged (only the tiny output layer shrinks).

are new.

## A. Build and size the firmware

```sh
make
riscv32-unknown-elf-size -A bin/main.elf     # -A separates model (.rodata) from code (.text)
```

Then load `bin/main.elf` onto Croc. Expected UART output (with trained weights):

```
KWS predicted class: <hex>
<keyword name>
expected: <hex>
```

> Ships with a **placeholder** `kws_model.h` (real dimensions, synthetic values)
> so it compiles and sizes before training. Predictions are meaningless until you
> run the exporter.

---

## B. Train and export

```sh
cd model
python3 -m venv .venv && source .venv/bin/activate
pip install torch torchaudio
python train_export_kws.py
```

Then point the output at the firmware include dir — edit in `train_export_kws.py`:

```python
with open("kws_model.h", "w") as f:        ->   with open("../lib/inc/kws_model.h", "w") as f:
```

The script trains the FP32 DNN, post-training-quantizes to int8 (including the
input zero-point folded into the layer-1 bias), runs an integer-only check whose
printed **int8 test acc** is the on-chip accuracy, and writes the header.

> The data pipeline (silence/unknown handling) is faithful but simplified. For a
> publishable accuracy number, use the official Speech Commands splits or the
> MLPerf Tiny KWS data prep.

## Memory budget

Same 16 KB unified SRAM as MNIST (`link.ld`). Measured from the actual arrays:

| Section            | Bytes  | What it is                                          |
|--------------------|-------:|-----------------------------------------------------|
| model weights+bias |  9,712 | W1 8000, b1 128, W2 1024, b2 128, W3 384, b3 48     |
| feature vector     |    250 | embedded MFCC test input (`.rodata`)                |
| activation buffers |    112 | h1 32 + h2 32 + logits 48                           |
| **model + buffers**| **~10.1 KB** | + ~3.5 KB shared code ⇒ **~13.5 KB / 16 KB** |

So the KWS classifier sits a bit heavier than MNIST (~10.4 KB), a useful second
row for the tiered "what fits in N KB" argument. The on-chip MFCC front end, if
added, is a separate ~4–7 KB on top — which is exactly the kind of number that
informs how much SRAM is worth paying area for.

---

## Quantization contract

Identical to the MNIST example, plus one addition:

- **Input layer:** MFCC features are signed, so activations use an **asymmetric
  uint8 zero-point `z_x`**. The correction `-z_x · Σ_j W1[o][j]` is folded into
  `kws_b1` by the exporter, so the C kernel is byte-identical.
- **Hidden layers:** ReLU outputs, zero-point 0 (as in MNIST).
- **Output layer:** raw int32 logits → argmax.

Class order is fixed and must match across `train_export_kws.py` (`LABELS`),
`kws_model.h`, and the `print_label()` switch in `kws_infer.c`:

```
0 silence  1 unknown  2 yes  3 no  4 up  5 down
6 left  7 right  8 on  9 off  10 stop  11 go
```
