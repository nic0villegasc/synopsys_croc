# MNIST int8 MLP on Croc (single-core Ibex)

A minimal TinyML example for the Croc SoC: a quantized **196 → 32 → 10**
fully-connected network that classifies 14×14-downsampled MNIST digits, running
bare-metal on a single Ibex core with **no external memory and no NN runtime**.

It exists to answer one question concretely: *how much on-chip SRAM does a useful
inference actually need?* For this model the answer is **~10.4 KB of the 16 KB
SRAM** (see [Memory budget](#memory-budget)).

The kernels are the scalar path of PULP-NN's `pulp_nn_linear.c` (Garofalo et al.,
UniBo/ETH) with the Xpulp SIMD and cluster code removed; the quantization is the
standard TFLite-style integer-only scheme.

## Directory layout

This README assumes the following layout (adjust paths if yours differs):

```
mlp_digit_classifier/
├── Makefile
├── config.h
├── crt0.S
├── link.ld
├── main.c                     # firmware entry point (from mnist_infer.c)
├── bin/  build/  test/
├── lib/
│   ├── inc/
│   │   ├── uart.h  print.h ...
│   │   ├── nn_linear.h
│   │   └── mnist_model.h       # GENERATED by the export script
│   └── src/
│       ├── uart.c  print.c ...
│       └── nn_linear.c
└── model/                      # host-only: Python + host C tests
    ├── .venv/
    ├── train_export_mnist.py
    ├── test_nn_linear.c
    └── mnist_demo_host.c
```

The firmware world (compiled for Croc) and the host/training world (Python +
host C) are kept separate; they meet only at the generated header
`lib/inc/mnist_model.h`.

## Prerequisites

- **Firmware:** the RISC-V GCC toolchain used by your Croc flow
  (`riscv32-unknown-elf-gcc`, `-size`, etc.) and whatever simulator/FPGA flow you
  already use to run `bin/main.elf`.
- **Host/training:** Python 3 and a host `gcc`. PyTorch is only needed to train.

---

## A. Build and size the firmware

`main.c` runs inference on the embedded test image and prints the predicted digit
over UART (in hex, since `print.c`'s `printf` only implements `%x`).

```sh
make                       # builds bin/main.elf
riscv32-unknown-elf-size bin/main.elf
```

To separate the model bytes (`.rodata`) from the code bytes (`.text`):

```sh
riscv32-unknown-elf-size -A bin/main.elf
```

Then load `bin/main.elf` onto Croc (RTL sim or FPGA) with your existing flow.
Expected UART output (with trained weights):

```
MNIST predicted digit: <d>
expected: <d>
```

> The repository ships a **placeholder** `mnist_model.h` (real dimensions,
> synthetic values) so the firmware compiles and sizes correctly before you have
> trained weights. Predictions are meaningless until you run the export step.

---

## B. Train the model and export weights

Run this on your machine (needs internet once to download MNIST):

```sh
cd model
python3 -m venv .venv
source .venv/bin/activate
pip install torch torchvision

python train_export_mnist.py
```

The script trains the FP32 model, post-training-quantizes it per-tensor to int8,
runs an integer-only check (the printed **int8 test acc** is what you get on-chip),
and writes the C header.

**One edit before running:** point the output at the firmware include dir. In
`train_export_mnist.py`, change

```python
with open("mnist_model.h", "w") as f:
```

to

```python
with open("../lib/inc/mnist_model.h", "w") as f:
```

Then rebuild the firmware (Part A) to bake the trained weights in.

## C. Verify on the host (optional but recommended)

Run from `model/`. These compile against the firmware sources directly and do
**not** go through the Makefile.

Kernel self-test — checks the int8 kernels by exact integer equality against an
independent reference:

```sh
gcc -O2 -I../lib/inc ../lib/src/nn_linear.c test_nn_linear.c -o test && ./test
```

Expected:

```
linear_out32   exact-match: OK   (32/32 outputs)
linear_u8_relu exact-match: OK   (32/32 outputs)
two-layer fwd  smoke      : pred=...  (in [0,9]: OK)
```

Full forward pass on the current `mnist_model.h`, plus a footprint readout:

```sh
gcc -O2 -I../lib/inc ../lib/src/nn_linear.c mnist_demo_host.c -o demo && ./demo
```

## Memory budget

From `link.ld`: one unified `SRAM` region, `ORIGIN = 0x10000000`,
`LENGTH = 16 KB`, holding **all** code, read-only data, writable data, and the
stack. The stack pointer starts at the top of SRAM (`0x10004000`) and grows down.
There is no flash and no heap, so the `dec` column of `size` is the real resident
footprint.

Reference measurement for this example:

| Section            | Bytes  | What it is                                            |
|--------------------|-------:|-------------------------------------------------------|
| `text`             | 10,290 | code + `.rodata` (incl. weights + embedded image)     |
| ├─ model constants | ~6,960 | `W1,b1,W2,b2` (~6.76 KB) + test image (196 B)         |
| └─ code            | ~3,330 | crt0, uart, printf, kernels, libgcc 64-bit multiply   |
| `data`             |     72 | activation buffers (`hidden[32]` + `logits[40]`)      |
| `bss`              |      0 | —                                                     |
| **total (`dec`)**  | **10,362** | **≈ 63% of 16 KB; ~6.0 KB free for the stack**    |

Stack use here is negligible (no recursion; buffers are `static`), so the model
fits comfortably. Use `size -A` to track the model (`.rodata`) and code (`.text`)
separately as you scale the network.

## Quantization contract

The C kernels and the Python exporter must agree on this exactly:

- **Activations:** `uint8`, zero-point = 0 (inputs in `[0,1]`, hidden = ReLU ≥ 0).
- **Weights:** `int8`, symmetric (zero-point = 0), per-tensor.
- **Bias:** `int32` in the accumulator domain, `b / (s_x · s_w)`.
- **Accumulate:** `int32`, `acc = Σ w·x + bias`.
- **Layer-1 requant:** `y = clamp_u8( round(acc · out_mult · 2^-out_shift) )`,
  ReLU folded into the lower clamp.
- **Layer-2:** raw `int32` logits → `argmax` (scale-invariant, no requant).

Weight arrays are row-major `[dim_out][dim_in]`, matching
`torch.nn.Linear.weight`.

## Notes / next steps

- The requant uses an `int64` intermediate (pulls in a libgcc 64-bit multiply).
  If a strictly 32-bit build matters, bound `out_mult` so `|acc|·out_mult < 2^31`
  and drop the cast.
- The same two kernels are the basis for the other planned examples (KWS, IMU
  gesture, anomaly autoencoder) — those reuse `nn_linear_*` and add a small
  feature front-end and/or a conv/depthwise kernel.
- For a citable, reproducible flow, the front half here (PyTorch → PTQ → integer
  params) can be swapped for **NEMO**; the back half (DORY/Deeploy tiling) is not
  needed on Croc, since the whole model fits in one flat SRAM.
